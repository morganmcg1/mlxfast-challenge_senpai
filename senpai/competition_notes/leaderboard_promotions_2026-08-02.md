## Executive summary

The snapshot contains **1,068 public submissions**: 126 accepted and promoted, one accepted whose promotion failed, 535 rejected, 400 failed, and six still validating. The 126 promoted successes came from **30 solvers** over roughly nine days.

The promoted line moved from score **1.003986005** to **2.454950621**, a **2.4452x** score multiple. Comparing the first and latest promoted candidates' absolute phase timings, decode fell from **13.567893 ms/token** to **5.249092 ms/token** (**61.31% lower**) and prefill fell from **0.382209 ms/token** to **0.195665 ms/token** (**48.81% lower**). The latest official component speedups are **2.646624x decode** and **1.959271x prefill**.

The broad story is not one silver bullet. The frontier compounded five kinds of work:

1. exact fusion and dispatch removal around attention, routing, residual/RMSNorm, and MoE;
2. better occupancy and physical scheduling in SDPA, QMV, gather-QMM, and host/Metal submission;
3. prefill-specific expert-run, permutation, and terminal-row work elimination;
4. lower decode weight traffic through staged attention side layouts, culminating in checkpoint NVFP4 across all attention layers; and
5. certified LM-head pruning and progressively tighter coarse representations.

The historical record is most useful as a set of measured priors. Several mechanisms changed sign after the frontier changed, after a compiler or GPU changed, or when a fusion duplicated work inside every consumer threadgroup. The right bootstrap is therefore to inherit and audit the current promoted source, then use these wins to choose experiments—not to mechanically replay old patches.

## Methodology

- Ran `git status --short --branch` before any inventory work and left the pre-existing untracked `senpai/leaderboard_survey_2026-07-29.md` untouched.
- Ran `mlxfast submissions --all` and captured the complete public response.
- Downloaded the benchmark submission JSON from `/api/benchmarks/1854efdf-feba-4773-bae9-b80520881a74/submissions`.
- Selected exactly `status == "accepted" && promotionStatus == "promoted" && promotedSourceRef != null`, matching the deployed leaderboard predicate.
- Retrieved every promoted submission's note with `mlxfast submission-note <full-uuid>`; all 126 CLI note files byte-match the API note plus its emitted newline.
- Sorted the ledger by `promotionFinishedAt`, not creation time. This yields the actual monotonic promotion sequence.
- Parsed model attribution from the first `Model:` line exactly as submitted; labels are intentionally not normalized.
- Defined **Δ vs prior frontier** as the submission score minus the highest score among earlier promotions. It is a leaderboard delta, not an isolated causal estimate: a promotion can inherit, restore, or compose several mechanisms, and official scores use paired session baselines.
- Linked submission IDs to the public per-submission API response, commits to the promoted upstream commit, and all 126 direct PRs. GitHub's commit-to-pulls endpoint found 103; submission-ID lookup recovered the remaining 23.

## How to read the ledger

- **Decode** and **prefill** cells are `speedup / absolute ms per token`.
- The per-row mechanism sentence is a concise reading of the public note, with the linked commit as the verification target.
- Each submission link opens the full public JSON record, including the complete note and official metrics; the site exposes row details in a modal rather than at a stable human-readable route.
- A large Δ does not prove the named mechanism alone caused the whole gain. Read the note, its stated base, and the actual commit ancestry before attribution.
- Promotions can restore work lost by whole-file overlays. The chronological source chain matters more than copying an old diff onto today's head.

It is deliberately excluded from the 126-row success ledger. Its note claims six carefully placed async rungs plus router-L6 and gated-output load-unroll changes. The rebased successor [de21429](https://mlx.fast/api/submissions/de214290-d449-4f3a-a3b1-fa70acac47b4) later promoted, so this is promotion-infrastructure provenance rather than an abandoned optimization result.

## Major outcomes worth inheriting

### 1. Exact fusion created the first durable decode foundation

The early frontier repeatedly removed tiny serial dispatches and intermediate BF16 tensors while preserving row ownership, reduction order, and rounding boundaries. Representative promotions are YaRN mscale folded into RoPE ([ab5009c](https://mlx.fast/api/submissions/ab5009cd-8db6-446a-bd76-de9ec32b9f6a)), exact router top-8 ([72bba60](https://mlx.fast/api/submissions/72bba602-7834-43eb-80ba-29632d586fdf)), residual plus RMSNorm ([21320d4](https://mlx.fast/api/submissions/21320d4a-c4ae-46b5-84c5-161dee72ab44)), and routed down projection plus expert reduction ([5bb1536](https://mlx.fast/api/submissions/5bb15364-25c8-4d16-8d67-d2fb3b211404)). The lasting pattern was not “fuse everything”; it was “fuse a dependency boundary only when the fused kernel does not duplicate the producer or worsen occupancy.”

### 2. Prefill became a first-class optimization axis

The first large prefill jump came from skipping empty expert runs in gather-GEMM ([404b2f5](https://mlx.fast/api/submissions/404b2f50-1b56-4c59-afed-31ecd7180448)). It was followed by expert-aligned gather scheduling ([96ceb7b](https://mlx.fast/api/submissions/96ceb7b9-009e-44ed-9eb9-ad746c77c363)), fused gate/up SwiGLU ([efc6872](https://mlx.fast/api/submissions/efc6872e-d590-4f1c-9345-b12d5210bf29)), a scatter-free MoE tail ([d0652d3](https://mlx.fast/api/submissions/d0652d39-6a26-4ba0-81d6-819670502a37)), and linear route-coordinate cleanup ([e17ee1e](https://mlx.fast/api/submissions/e17ee1e5-7423-4a08-b1d9-a9762ad22ba5)). Later EG128/EG256, split-K fusion, wider staging, QK-norm/RoPE repartition, and terminal-row reuse continued this line.

The practical lesson is to profile the exact 512-token geometry. Sorted expert runs, inverse permutations, and terminal-row semantics create opportunities that do not exist in single-token decode.

### 3. Host/GPU overlap and process lifetime mattered

A layer-33 asyncEval cut ([b3889ed](https://mlx.fast/api/submissions/b3889ed8-d19b-4316-ae03-1c2aa5b81965)) became a two-rung schedule, then a streaming ladder ([6dd236c](https://mlx.fast/api/submissions/6dd236c2-9d28-4f19-b51d-d88bdccafcf2)) and stride-tuned prefill/decode ladders ([0c1ab7f](https://mlx.fast/api/submissions/0c1ab7f8-b4d9-4d01-b50c-b04becf15d63)). Wired residency ([cb418c4](https://mlx.fast/api/submissions/cb418c4c-d68b-4c65-a4bc-3d9dd55317e2)) attacked driver re-residency. Greedy-argmax warmup ([e885776](https://mlx.fast/api/submissions/e885776f-6af6-4f77-9c48-90fc7ca7fb49)) kept first compilation out of timed windows.

This is an important reminder that the scored path includes graph construction, JIT state, command-buffer policy, and fresh-worker behavior—not just Metal kernel body time.

### 4. Attention weight traffic drove the largest decode era

The frontier first replaced BF16 QKV and output-projection reads with group-32 affine INT8 side layouts in band-sized chunks: QKV from 16 layers to all 40 ([724f8e5](https://mlx.fast/api/submissions/724f8e52-38ff-44b8-a3e9-40b4de5c6805) through [4268218](https://mlx.fast/api/submissions/42682184-5e73-4a88-9340-ec094a334ac3)), then output projection from 16 to 40 layers ([8afa931](https://mlx.fast/api/submissions/8afa9316-a9db-40aa-bf99-508801c31faf) through [88d8fe2](https://mlx.fast/api/submissions/88d8fe26-224b-4a18-ad42-a56c7e317712)).

The decisive later realization was that the checkpoint's own group-16 NVFP4 representation is roughly half the bytes of the affine INT8 side layout. The NVFP4 suffix widened from layer 32 to 24 ([8449082](https://mlx.fast/api/submissions/8449082c-4dc2-4526-b3bd-69712c3b8a8e)), then to the individually tested boundary 17 ([df2a748](https://mlx.fast/api/submissions/df2a7483-9c5b-4f4c-8a2f-9fee780515d7)), and finally to all 40 layers with the format-aware fusion floor unlocked ([db17321](https://mlx.fast/api/submissions/db173215-a7d7-4863-a333-8132c33be279)). That sequence explains much of the late jump from roughly 2.12 to 2.37.

The transferable principle is byte accounting against the *current* representation. “Quantized” is not a sufficient description; group size, metadata bytes, retained side banks, and which original tensors remain resident all matter.

### 5. LM-head work was reduced by proof, not wishful pruning

The vocabulary head evolved from a corrected certified two-pass path ([e36827e](https://mlx.fast/api/submissions/e36827ee-3687-406b-9521-0e14f43a9e91)) through fused thresholds, MXFP8 coarse scheduling, planar INT6 ([f03984b](https://mlx.fast/api/submissions/f03984b6-98bb-4a79-99d1-8248c214faa1)), exact ratio/delta bounds, midpoint thresholds, and a certified INT5 coarse arm in the compound winner ([42835ff](https://mlx.fast/api/submissions/42835ffe-aa47-4658-9f75-9b0e7509752f)). The recurring successful shape was: cheap conservative screen, mathematically sound candidate certificate, then exact BF16 evaluation for all surviving rows.

That is a strong template for future output-head work: reduce bytes and candidate count while proving that the exact winner cannot be discarded.

### 6. The final frontier was won by re-auditing inherited defaults

After all-attention NVFP4, [a0da915](https://mlx.fast/api/submissions/a0da915f-450a-4063-bf8e-ec1661f4a661) gained the largest late step by turning a prior fusion off: separate RMSNorm, NVFP4 QKV, and affine gate dispatches beat a fused kernel that recomputed normalization in every output tile. [4173c40](https://mlx.fast/api/submissions/4173c401-0f25-41fd-bec7-cdea22a1aac3) then kept only two mechanisms with positive absolute M5 receipts, and [05e7894](https://mlx.fast/api/submissions/05e7894f-0eaf-4f6d-8622-499d1e44185d) added the final one-row down retile.

The frontier is therefore not simply the union of every prior optimization. It is a curated set whose profitability depends on the surrounding source and target compiler.

## Negative evidence and course corrections

- **Fusion can lose.** [a0da915](https://mlx.fast/api/submissions/a0da915f-450a-4063-bf8e-ec1661f4a661) is the clearest counterexample: one extra dispatch was cheaper than duplicating an RMS reduction and barriers in every fused consumer group.
- **Fewer dispatches can lengthen a dependency chain.** [796ebd8](https://mlx.fast/api/submissions/796ebd80-9afe-466f-a071-aa400316d5c7) unmerged routed and shared gate/up QMV because independent kernels overlapped better.
- **A cache can become baggage.** [3f76381](https://mlx.fast/api/submissions/3f76381f-17e8-4745-be4d-2a7ce84b7cad) retired the decode RoPE atlas after auditing its marginal value on the evolved stack.
- **Exact-token risk is nonmonotonic.** The public note for [df2a748](https://mlx.fast/api/submissions/df2a7483-9c5b-4f4c-8a2f-9fee780515d7) reports NVFP4 boundaries 18 and 19 failing a near tie while boundary 17 passed. Test candidate boundaries individually; do not assume more numeric perturbation monotonically means more token failures.
- **Dormant flexibility can still cost registers.** [70a3ad4](https://mlx.fast/api/submissions/70a3ad4b-70da-4b17-ab4f-388945dfee29) attributes ranked regressions to a runtime-bounded geometry branch that polluted the whole PSO even when its stock-looking default was selected.
- **Local signs do not always transfer.** [a714393](https://mlx.fast/api/submissions/a714393a-f61e-45db-8d0d-41185a5ea1b5) and [05e7894](https://mlx.fast/api/submissions/05e7894f-0eaf-4f6d-8622-499d1e44185d) document architecture-specific reversals. The official M5 result is the authority for NAX geometry and occupancy.
- **The best command-buffer regime moves.** It was retuned after residency and again after loader changes ([7a5bfed](https://mlx.fast/api/submissions/7a5bfede-b262-4508-9abd-0da23aab580a), [6b36902](https://mlx.fast/api/submissions/6b369022-5c92-45bf-bfe4-3a926e146ece)); treat it as a coupled system parameter.
- **Measurement setup can masquerade as a model regression.** [8449082](https://mlx.fast/api/submissions/8449082c-4dc2-4526-b3bd-69712c3b8a8e) traces a first-prefill idle penalty, while [e885776](https://mlx.fast/api/submissions/e885776f-6af6-4f77-9c48-90fc7ca7fb49) removes compile work from timed windows.
- **Paired-score noise can hide small absolute wins.** [42835ff](https://mlx.fast/api/submissions/42835ffe-aa47-4658-9f75-9b0e7509752f) explicitly compares absolute candidate phases across sessions. Record absolute decode and prefill, paired baselines, and score; do not update beliefs from verdict alone.
- **Whole-file promotion overlays can erase orthogonal wins.** Restorations appear repeatedly in [b27c7b5](https://mlx.fast/api/submissions/b27c7b54-c162-499f-99ae-81dd58c7aa33), [59052c2](https://mlx.fast/api/submissions/59052c21-d058-40e3-9a66-909e62b67789), and [9847ff8](https://mlx.fast/api/submissions/9847ff8f-918e-4988-ba2f-a1137d23784b). Audit the value graph after every sync.
- **Acceptance-band chunking shaped the history.** QKV, output-projection INT8, wired residency, and NVFP4 widening were deliberately staged. Continue to follow the current frozen contract even when historical runs appear to have landed outside an expected band.

## Recommended bootstrap for our campaign

1. **Start from promoted commit [7702fab](https://github.com/Layr-Labs/mlxfast-challenge/commit/7702fab8a41fe2f4ff2ae281beeb1548b31e3406), not from an old patch series.** Preserve the current dirty worktree before any sync.
2. **Build a current-head mechanism map.** Record every default-on path, environment ablation, weight side bank, warmup, and promoted commit that owns it. Remove assumptions based only on historical titles.
3. **Re-profile bytes and dependency gaps on the current stack.** The notes suggest attention bytes are now near their representation floor, so remaining decode opportunity is more likely in MoE, LM-head, small-op scheduling, and host/FFI gaps; verify this rather than taking it on faith.
4. **Prefer reversible, attributable experiments.** Same-binary kill switches, one source hypothesis at a time, interleaved A/B order, cool starts, absolute phase timings, and exact-token controls were the strongest recurring practice.
5. **Use exact layout and scheduling changes before numerical reassociation.** Repack metadata, change row ownership, share immutable carriers, and move submission boundaries while keeping operation order stable.
6. **Price the whole dependency chain.** Count saved bytes, duplicated producer work, barriers, live registers, independent waves, and queue overlap—not just launches or FLOPs.
7. **Treat numerical format changes as staged behavioral experiments.** Probe individual layer boundaries and logit margins; hidden near ties can be nonmonotonic.
8. **Bundle only when the evidence says components compose.** Small sub-1% mechanisms are hard to resolve against paired noise, but broad speculative bundles are hard to diagnose. A small set of orthogonal mechanisms with independent receipts is the useful middle.
9. **Keep an independent-ideas budget.** The ledger is a launchpad, not a search boundary. Reserve profiling time for mechanisms not represented here, especially after the current frontier has invalidated many old bottleneck assumptions.
