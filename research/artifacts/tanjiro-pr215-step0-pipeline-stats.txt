================================================================================
IMPLIED THREADGROUPS PER SHADER CORE
================================================================================

Ranked geometry (quantized.cpp variant 5): bm=64 bn=64 wm=4 wn=1
  -> 128 threads per threadgroup, threadExecutionWidth 32
  -> 4 simdgroups per threadgroup.

Two independent residency constraints bound threadgroups per core:

  (1) threadgroup-memory pool.  With a per-core threadgroup-memory pool of P bytes,
      TGs/core = floor(P / tgMem_B).  For the standard 64 KiB Apple per-core pool:
        control : floor(65536 / 9232) = 7
        arm 1   : floor(65536 / 9232) = 7
      This bound is INVARIANT under P: tgMem_B is bit-identical between the two
      variants, so whatever the true pool size, the two variants get the same number.

  (2) simdgroup slots.  The M5 occupancy ladder for this core is 32 simdgroups/core at
      <= 104 half-registers, falling to 26 / 20 / 16 / 12 at 128 / 160 / 208 / 256.
        at <=104 half-regs: floor(32 / 4) = 8 TGs/core
        at   128 half-regs: floor(26 / 4) = 6 TGs/core
        at   160 half-regs: floor(20 / 4) = 5 TGs/core

  Binding constraint = min of the two.

  variant   tgMem_B   TGs/core (tgmem, P=64KiB)   TGs/core (simd, <=104 half-reg)   binding
  control      9232                           7                                 8         7
  arm 1        9232                           7                                 8         7

  => 7 threadgroups/core = 28 resident simdgroups/core, IDENTICAL for both variants,
     unless the arm crossed a register step. maxTotalThreadsPerThreadgroup would have
     dropped below 1024 only at >= 64 half-registers/thread; it did not drop, but that
     test saturates well below the 104 cliff, so it does not by itself exclude a step.
